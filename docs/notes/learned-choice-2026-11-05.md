# 单字母选词学习排查

用户反馈 `m` 选「吗」后下一次仍非首选。基线 `c2f803e8`。未读取用户机器配置或学习文件，不能将沙箱中的结果当作已确认用户的设置。

使用真实 data-v9 主词库和 `FrequencyLearner`，无模型查询 `m`，首选「没」，选择「吗」后 `choice_weight("m", "吗") = 1`，断开上文再查，首选变为「吗」。输入串记录和基础排序都能即时生效。默认配置 `general.learning = true`，Windows 启动与热加载都会应用此设置。

但 `Engine::rerank_choices` 在词级排序之后按知意模型、语言模型和位置先验决定首选，没有保护同输入的学习结果。真实学习器配合可控模型能复现：选「吗」后查询先返回「吗」，后台模型强烈偏爱「没」时，下一次查询改回「没」。新增回归先验证此断言失败，再修复。该复现证明代码允许覆盖，不代表实际知意权重在所有上下文都会这么排。

修复仅在比较组第一条已带有同输入选择记录时跳过知意选词重排；不提升其他匹配等级的低位学习项，不影响未学习输入的模型重排。单字母学习只绑定 `m`，不泛化为 `ma`；已有历史记录按次数比较，最近一次选择不保证覆盖大量历史选择。固定第一位应使用候选右键的「置顶」。

跨 crate 回归使用四词独立词库和真实学习器，验证第四项选择即时生效、保存重载、关闭学习和私密输入不记录、模型不能覆盖。用户可先在新记事本中确认「设置 → 候选 → 学习输入习惯」打开，关闭知意后用 `m` 选「吗」，保留上屏文字再查；删除刚上屏的字后重打可能触发撤销学习，不能作为同一测试步骤。

现有安装包源码为 `7d2fb9d0`，不含本次修复。本次修改尚未在原生 Windows/用户输入框复验，不将先前安装包的通过记录当成本次原生验收。

验证：Linux 适用 workspace 1,737 项通过、0 失败、6 默认忽略；fmt、严格 workspace Clippy、Windows GNU Server/TSF 全 targets 严格 Clippy 通过。新增 4 项真实学习器集成回归全部通过，修复前只有模型覆盖项失败。
