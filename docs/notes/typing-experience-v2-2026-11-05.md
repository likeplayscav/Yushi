# 体验回放扩展与首次逐字造词

用户反馈输入仍有迟滞，希望增加三至四字短语、真实编辑动作，以及逐字拼出新词后立即记住。本轮只本地验证与提交，不触发 Actions、不生成产品安装包。

## 本机能编什么

本机是 Linux，已安装 Rust `x86_64-pc-windows-gnu` 标准库及 MinGW GCC。使用 `rustc --target x86_64-pc-windows-gnu` 完成了最小程序的实际链接，`file target/local-windows-probe/probe.exe` 确认为 PE32+、x86-64 Windows 可执行文件。这证明可以生成 Windows exe，不代表整套青简 Windows 产品已成功交叉编译或运行。

现有正式安装脚本还会构建 `i686-pc-windows-msvc` TSF DLL，并调用 Inno Setup。当前没有 MSVC/Windows SDK、Inno Setup 或 Wine，也不能运行 Win11 的 TSF、签名/UIAccess 与安装验收。默认仍在本机做 GNU 目标检查，把完整安装包与原生验收集中到最终一次 Windows 构建；不为证明工具链而提前构建安装包。

## 回放与证据

原 50 条与原基线逐条保留，扩展 81 条，总计 131 条。24 个独立短语各有全拼、简拼、错键/退格三种键流；三组连续会话保留上下文，覆盖聊天、办公、中文切英文再切回。默认启用产品实际的暂存组句，全部选完才输出文字。

新增题目先在造词修复前的引擎上回放，记录入 `reference-v2.json`。第一轮暴露 `zyaq` → “注意安全”未命中、单字翻 45 页仍未完成。回放现在允许在简拼单字三页还找不到时取消并改全拼。补救全程记入操作数，初次预测依然记失败；门禁独立要求全部任务最终完成，不能以基线里曾失败为由放行。

相同状态的重复查询仅用于稳定性，热缓存时间单列。响应分改用包含按键/退格/上屏与随后查询的事件时间，另用 50ms/80ms 虚拟键间隔推算单线程排队。它不等待人为间隔，也不模拟 Windows 调度、IPC、绘制或后台神经模型。

本机 release 回放 `target/experience/upgrade-verified/` 的结果：

| 指标 | 结果 |
| --- | ---: |
| 全部任务 | 131/131 完成 |
| 初次 Top-1 / Top-5 | 85.50% / 92.37% |
| 三字 / 四字全拼首选 | 12/12、12/12 |
| 三字 / 四字简拼首选 | 7/12、6/12 |
| 学习与交互检查 | 18/18 |
| 评分 | 94.26/100 |
| 操作数 / 翻页数 / 全拼补救 | 1726 / 14 / 2 |

| 最慢事件 / 虚拟排队 P95 | 8.09 / 4.13ms |

总分与旧 50 条测试的 94.08 不直接比较：题目、学习检查、事件计时都变了。没有据此修改词库或提高默认排序分数。原 50 条逐条准确度与完成未退步。报告包含源码提交及工作区状态、二进制/词库/样例指纹；构建安装包时沿用原入口自动执行升级后的门禁。

## 首次造词

原实现同段分选要求累计两次，首次不会进入用户词。现在仅当同段拼音选完、2–4 字全部经过单字明确选择时，第一次就调用已有用户词学习路径，沿用 `user-words.tsv`，无需新配置或文件格式。主词库已有词不重复添加；词组接续/模型整句保留原阈值，跨输入仍需三次。

`CommitChain::buffer_has_implicit` 标记模型拆出的词，避免自动整句恰好拆成单字时被误判为逐字确认。7 个专项测试中首次保存与重载两项在修复前失败、修复后通过；覆盖 2/3/4 字、暂存/即时上屏、简拼后全拼、保存重载、隐私/禁学习、取消未完成、跨段/标点、超长词与模型整句边界。产品数据下再增加 7 项交互门禁。

## “不跟手”仍需真机证据

本轮静态引擎事件未超过 16.67ms，不能认定已修复 Win11 体感迟滞。Windows 源码中，首轮候选立即生成；30ms 防抖用于随后后台模型重排。Server 每 60 秒在处理消息时顺带保存学习数据，此外还有管道往返和候选绘制，均可能与 Core 回放不同。

新增 `Slow input event` 日志记录超过 17ms 的 Server 处理，分别报告消息分派与定时学习保存时间，不记录输入内容。现有绘制调试日志可配合定位。这个日志测不到客户端等待与异步绘制；下一次最终包安装后，需结合用户发生卡顿的应用和时刻判断瓶颈，不凭静态回放盲目改模型节拍。
